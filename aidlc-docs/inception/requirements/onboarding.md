## Functional Requirements

| ID | Requirement | Source | Acceptance |
|---|---|---|---|
| **FR-44** | **가입 시 관심사 수집 [U14/U5]**: 신규 사용자 가입 플로우에서 **arXiv 카테고리 픽커**(v1 수집 UX — OQ-2)로 연구 관심사를 수집한다. 입력은 **스킵 가능**(OQ-3 — 가입 완료를 막지 않음). **기존 사용자에게도 다음 로그인 시** 동일 픽커를 프롬프트한다(OQ-4). | roadmap §5.1 · OQ-2/3/4 결정 | 가입 플로우와 기존 사용자 차기 로그인에서 픽커가 노출되고, 선택 결과가 FR-45 시딩 입력으로 전달된다. 스킵 시 가입/로그인은 정상 완료되고 비개인화 경로로 동작한다. |
| **FR-45** | **U9 프로필 시딩 [U9/U14]**: 수집된 관심사를 **관심사 설정 행동 이벤트**(FR-39 개정 — 온보딩은 사용자가 관심사를 직접 설정하는 의미 있는 행동)로 기록해 기존 FR-19 집계 경로로 프로필(`categoryWeights` **+** `keywordWeights` — OQ-1)을 시딩한다. 시드는 **고정 반영이 아니다**(OQ-5): 이후 행동 이벤트가 쌓이며 자연히 우세해지고, raw 이벤트 90일 보관 정책이 시드의 자연 감쇠를 제공한다. **US-P5(키워드 부스트 라이브 소비)를 본 트랙에 묶어 선행**한다(OQ-1). | roadmap §1·§5.1 · OQ-1/5 결정 | 관심사를 제공한 사용자의 프로필에 시딩 신호가 비어 있지 않고, FR-20 적용 경로가 별도 랭킹 기계 신설 없이 소비한다(카테고리는 라이브 US-P4, 키워드는 선행된 US-P5). 시딩 이벤트도 FR-19 사용자 통제(끄기·삭제·초기화)와 QT-7 불변식(동일 이벤트 집합 → 동일 프로필)에 그대로 걸린다 — 직접 프로필 기록 금지. |
| **FR-46** | **ORCID 관심사 유도 시딩 [U14/U3]**: ORCID 로그인 사용자(#347 라이브)는 ORCID **프로필·저작(works)** 에서 관심사를 유도해 FR-45와 동일한 시딩 경로에 공급한다(OQ-6). | OQ-6 결정 · #347 | ORCID 유도 관심사가 관심사 설정 이벤트로 기록되어 프로필에 반영된다. 유도 데이터도 owner-scoped(SEC-8)이며, ORCID 조회 실패 시 픽커-only로 저하(가입/로그인 무영향, NFR-P4). |

## Non-Functional Requirements

신규 NFR 없음 — 기존 NFR이 그대로 적용된다:

| 기존 ID | 적용 방식 |
|---|---|
| **NFR-P4 [U9]** | 시딩 기록·집계가 가입/로그인 핵심 응답을 지연시키지 않고, 실패 시 비개인화 경로로 저하. |
| **QT-7 [U9]** | 시딩은 이벤트 경로만 사용(OQ-5) → 집계 불변식(동일 이벤트 집합 → 동일 프로필, 초기화 후 신호 제거) 유지. |
| **SEC-8** | 시딩·ORCID 유도 관심사 모두 owner-scoped 비공개 데이터. |

## Constraints

| ID | Kind | Constraint | Source |
|---|---|---|---|
| **C-7** | technical | 시딩은 기존 U9 이벤트·프로필 집계 계약 안에서 수행한다(직접 프로필 기록 금지 — TTL/재집계에 소실됨). §12 U9 제외 항목(별도 추천 목록·실시간 ML·강한 순위 변경)을 재도입하지 않는다. | requirements.md §12 · OQ-5 결정 |
| **C-8** | business | Phase 3 실행 순서상 온보딩(U14)이 첫 항목 — 트렌드/알림·구독제에 앞서 개인화 콜드스타트 해소가 선행된다. US-P5는 본 트랙에 포함해 선행한다. | roadmap §5·§6 · OQ-1 결정 |
